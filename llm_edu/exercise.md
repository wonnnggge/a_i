RAG·도구 호출·에이전트는 다음 과정이고, 여기서는 지금까지 배운 것만으로 만듭니다.

## 1. 무엇을 만드나

긴 보안 공지문을 넣으면 **네 항목으로 요약**하는 봇을 만들고,
**어느 모델이 이 일을 가장 잘하는지 숫자로** 가립니다.

```
공지문 (영문, 수백~수천 자)
        ↓
제품 / 영향 / 조치 / 긴급도   ← 네 줄로
        ↓
모델별 정답률 · 토큰 · 비용 표
```

### 데이터

`advisories_sample.json` — 실제 공개 공지 **10건**입니다. 직접 만들 필요 없습니다.

| 필드 | 내용 |
|---|---|
| `no` | 1 ~ 10 |
| `cve_id` | CVE 번호 |
| `label` | 제품 이름 (채점용, **모델에게 주지 마세요**) |
| `advisory` | 공지 본문 — 이것만 모델에게 줍니다 |

### 비교할 모델

**클라우드 2개 + 내 PC 로컬 2개**, 모두 네 개입니다.

| | 모델 | 돈 | 공지문이 나가는 곳 | 쓴 노트북 |
|---|---|---|---|---|
| 클라우드 | `gpt-4.1-mini` | 토큰당 과금 | 외부 API 서버 | `1_1_openai` |
| 클라우드 | `gpt-4.1-nano` | 토큰당 과금 (더 쌈) | 외부 API 서버 | `1_1_openai` |
| 로컬 | `qwen2.5:3b` | **0원** | **내 PC 밖으로 안 나감** | `1_3_2_qwen` |
| 로컬 | `llama3.2` | **0원** | **내 PC 밖으로 안 나감** | `1_3_ollama` |

보안 업무에서는 오른쪽 두 열이 장점이 아니라 **조건**일 때가 많습니다.
사내 자산 정보가 섞인 공지를 외부 API 로 보낼 수 없는 조직이 있기 때문입니다.
그래서 이 과제의 진짜 질문은 이것입니다.

> **공짜이고 밖으로 나가지 않는 대신, 무엇을 얼마나 잃는가?**

로컬 모델을 **두 개** 넣은 것도 일부러입니다. 같은 3B 급이라고 결과가 같지 않습니다.

> Claude 와 Gemini 는 쓰지 않습니다. **OpenAI 키 하나**와 Ollama 만 있으면 끝낼 수 있습니다.
> 로컬 모델이 없다면 터미널에서 받으세요 — `ollama pull qwen2.5:3b`, `ollama pull llama3.2`

## 2. 요구사항

### 필수 1 — 요약 프롬프트 만들기 (1_1, 1_1_2)

공지문을 받아 **정확히 네 줄**로 답하게 하세요.

```
제품: <제품 이름과 영향받는 버전>
영향: <공격자가 무엇을 할 수 있나, 한 문장>
조치: <어느 버전으로 올리나. 공지에 없으면 "공지에 없음">
긴급도: <긴급|높음|보통|낮음>
```

지켜야 할 것

- `temperature=0` — 같은 공지에 같은 답이 나와야 비교가 가능합니다
- `system` 프롬프트에 **"공지에 없는 내용은 지어내지 말 것"** 을 넣으세요
- 모를 때 쓸 말(`"공지에 없음"`)을 **미리 정해 주세요.** 이 한 줄이 있고 없고의 차이는 직접 재 보세요
- `max_tokens` 를 정하되, **잘리면 안 됩니다**

> **힌트 — `max_tokens` 는 모델마다 다르게 필요할 수 있습니다.**
> 어떤 모델에서만 `finish_reason` 이 `length` 로 쏟아진다면, 그 모델이 요약을 못하는 것이 아니라
> **예산이 모자란 것**일 수 있습니다. 그 모델만 값을 올려 보고 결과가 달라지는지 확인하세요.
> 설정이 불공평하면 비교 자체가 무의미해집니다.

### 필수 2 — 모델을 데이터로 다루기 (1_4)

```python
MODELS = {
    "gpt-4.1-mini": (openai_client, "gpt-4.1-mini"),
    "gpt-4.1-nano": (openai_client, "gpt-4.1-nano"),
    "qwen2.5:3b":   (ollama_client, "qwen2.5:3b"),
    "llama3.2":     (ollama_client, "llama3.2"),
}
```

- 모델을 추가할 때 **이 딕셔너리에 한 줄만** 넣으면 되게 만드세요
- 로컬 모델도 **같은 `OpenAI` 클래스**로 부릅니다. `base_url` 만 다릅니다 (`1_3_ollama`)
- 호출 함수는 클라우드인지 로컬인지 **몰라도 되게** 만드세요
- `try` / `except` 로 감싸서 **한 모델이 실패해도 나머지는 끝까지** 돌아야 합니다

### 필수 3 — 토큰과 비용 재기 (1_5)

- `tiktoken` 으로 **보내기 전에** 입력 토큰을 셉니다
- 응답의 `usage` 로 실제 입력·출력 토큰을 기록합니다
- 모델별 **총 토큰**을 표로 냅니다

> 비용 단가는 모델마다 다르고 자주 바뀝니다. 금액 계산은 선택이고,
> **토큰 수 비교**까지가 필수입니다.
>
> 로컬 모델은 토큰 단가가 0 입니다. 대신 **시간**을 씁니다.
> `seconds` 를 꼭 기록하세요 — 로컬 모델에서는 그게 비용입니다.

### 필수 4 — 잘림 검사 (1_1_2)

- 응답마다 `finish_reason` 을 확인합니다
- `length` 가 나오면 **그 답은 잘린 것**입니다. 몇 건이나 잘렸는지 세세요
- 눈으로 보기에 멀쩡해도 잘렸을 수 있습니다. 내용이 아니라 `finish_reason` 을 보세요

**잘림이 많은 모델이 있다면 거기서 멈추지 마세요.**
`max_tokens` 를 올려 다시 돌려 보고, 그래도 잘리는지 확인한 뒤에 결론을 쓰세요.
잘린 답으로 매긴 점수는 모델의 실력이 아니라 **내 설정을 측정한 것**입니다.

### 필수 5 — 채점하고 표로 내기

채점 기준은 **세 가지**입니다.

| 항목 | 판정 방법 |
|---|---|
| **형식** | 네 줄(`제품:` `영향:` `조치:` `긴급도:`)이 모두 있는가 |
| **제품** | 정답 제품 낱말이 답에 들어 있는가 |
| **조치** | 정답 버전 낱말이 들어 있는가 |

채점표(정답)는 아래 **4장**에 있습니다. 그대로 쓰세요.

> **`지어냄 0` 만 보고 모델을 고르지 마세요.**
> 모든 공지에 `조치: 공지에 없음` 이라고만 답해도 지어냄은 0 입니다.
> 호출이 전부 실패해 답이 하나도 없어도 0 입니다.
> **조치 점수와 오류 건수를 반드시 같이** 보세요.

- 모델별 전체 답변
